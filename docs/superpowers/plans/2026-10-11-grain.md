# grain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `grain`, a current-state source-size and estimated-complexity dashboard distributed by chezmoi and usable in any repository.

**Architecture:** Normalize scc JSON through an injected process boundary; keep selection, statistics and state transformations deterministic. Wire concrete subprocess, filesystem and OpenTUI adapters only at the entry point. Preserve the invoking directory through the deployed launcher.

**Tech Stack:** Bun >=1.3.0, TypeScript, @opentui/core 0.5.12, external scc.

**Spec:** `docs/superpowers/specs/2026-10-11-grain-design.md`

## Global Constraints

- Use total physical lines, including comments and blanks, not code-only lines.
- Include tests and QA by default, with an exclusion option.
- No history, watching, caching, automatic dependency installation at invocation, or editing analyzed files.
- Both numeric fields must be finite, nonnegative safe integers.
- Use Bun >=1.3.0 and pinned `@opentui/core` 0.5.12, matching the existing Todoist application.
- Do not introduce a React/Solid wrapper or a runtime validation library.
- QA is manual/discretionary, never added to hooks or CI.
- Read the spec's exact language/path policies, bucket boundaries, controls and CLI grammar before implementation; these are requirements, not examples.
- Scope all apply/diff operations; do not apply unrelated host changes. No isolated workspace is requested.

## Review Focus

- Empty populations and boundary values must not produce NaN, bad percentiles, or lose files between buckets (Task 1).
- Source-language configuration and unmarked generated code must not be represented as perfectly classifiable; explicit exclusions win (Task 1).
- Paths with spaces, Unicode, control characters and leading dashes must remain literal, root-contained paths and never become shell syntax (Tasks 1–2).
- Invalid, partial, future-additive or failed scc output must distinguish a legitimate empty scan from an error (Task 2).
- Query input must accept q/s/j/k as text, and quitting/errors must restore the terminal; confirm interactively, not with UI unit tests (Task 3 QA).

## File map

- `dot_config/grain/model.ts`: FileMetric, options, selection and analysis, pure dashboard state.
- `dot_config/grain/scanner.ts`: ProcessRunner interface, process result decoding, normalization, scan orchestration.
- `dot_config/grain/main.ts`: CLI composition root and lifecycle, no domain logic.
- `dot_config/grain/ui.ts`: render and event cleanup.
- `dot_config/grain/{package.json,bun.lock,tsconfig.json}`: pinned app runtime, local strict typecheck configuration.
- `dot_local/bin/executable_grain`: cwd-preserving launcher.
- `run_onchange_after_install-grain-dependencies.sh.tmpl`: policy-aware, frozen local dependency installation.
- `tests/grain-{model,scanner}.test.ts`: deterministic tests, no real processes or terminal.
- `.gitignore`, `.chezmoiignore`: exclude grain/node_modules using source and target naming respectively.
- `docs/qa/grain.md`: scope, usage, limitations, discretionary integration and human-driven terminal checks.

### Task 1: Source selection and distribution model

**Files:** Create `dot_config/grain/model.ts`, `tests/grain-model.test.ts`.

**Interfaces:**
- `FileMetric = { path: string; language: string; totalLines: number; complexity: number }`.
- `Options = { directory: string; exclusions: string[]; excludeTests: boolean; languages: string[] | null; help: boolean }`.
- `parseArgs(args: readonly string[]): Options`; defaults directory to `.`, with other defaults from the spec. Throws an Error with actionable message for invalid syntax.
- `selectFiles(files: readonly FileMetric[], options: Options): FileMetric[]` owns all source policy. Export `EXCLUDED_DIRECTORIES: readonly string[]` for scanner use.
- `SortMetric = 'totalLines' | 'complexity'`.
- `DashboardState = { query: string; sort: SortMetric; selectedIndex: number }`.
- `DashboardAction = { type: 'query'; value: string } | { type: 'sort' } | { type: 'move'; delta: number }`.
- `HistogramBin = { label: string; min: number; max: number | null; count: number }` (inclusive bounds, null upper bound means unbounded).
- `MetricSummary = { median: number | null; p90: number | null; bins: HistogramBin[] }`.
- `Distribution = { files: FileMetric[]; fileCount: number; totalLines: number; lines: MetricSummary; complexity: MetricSummary }`.
- `analyze(files: readonly FileMetric[], query: string, sort: SortMetric): Distribution`.
- `updateDashboard(state: DashboardState, action: DashboardAction, files: readonly FileMetric[]): DashboardState`; query and sort reset selection to zero; movement clamps to visible rows, empty selection is zero.
- `displayPath(path: string): string` replaces C0/DEL/C1 control characters with visible escaped representations, leaving ordinary Unicode unchanged.

- [ ] **RED — contracts and tests:** Add minimal compilable stubs and tests named for behavior. Assert lines `[0,99,100,199,200,299,300,499,500,999,1000]` yield bucket counts `[2,2,2,2,2,1]`; complexity `[0,1,9,10,29,30,59,60,99,100]` yields `[1,2,2,2,2,1]`. Assert values `[1,2,3,4]` give median 2.5 and p90 4; empty gives null percentiles, six zero bins and total 0. Assert 10 sequential values give p90 9. Confirm input arrays are unchanged.
- [ ] **RED — policy/state tests:** Assert TypeScript and extensionless Shell are included, JSON/Go Template and excluded path segments/config basenames are not; tests/QA are included until excludeTests is true; explicit globs beat language overrides; literal case-insensitive query affects rows and every aggregate together. Cover all listed test filename patterns, zero results and movement bounds. Assert equal metrics sort by path consistently. Assert unknown/missing CLI options, two targets, help, and `-- -repo` semantics. Assert a path with `\u001b`, newline and Unicode is escaped only for display.
- [ ] Run `bun test tests/grain-model.test.ts`; confirm intended assertion failures rather than import failures.
- [ ] **GREEN:** Implement the defined functions with the spec's exact allowlist, exclusions, bucket boundaries and nearest-rank rule. Use Bun.Glob for exclusions; no filesystem access in model code.
- [ ] Run `bun test tests/grain-model.test.ts` and `git diff --check`; require no failures.

### Task 2: scc adapter and process boundary

**Files:** Create `dot_config/grain/scanner.ts`, `tests/grain-scanner.test.ts`.

**Interfaces:**
- Consumes Task 1's FileMetric, Options, selectFiles and EXCLUDED_DIRECTORIES.
- `ProcessRequest = { argv: readonly string[]; cwd: string }`.
- `ProcessResult = { exitCode: number; stdout: string; stderr: string }`.
- `ProcessRunner = { run(request: ProcessRequest): Promise<ProcessResult> }`.
- `decodeMetrics(output: string, root: string): FileMetric[]`; normalize using lexical path operations only, consume per-file `Location`, `Language`, `Lines`, `Complexity`, and optional Binary/Generated/Minified flags. Validate language groups have Files arrays; reject malformed records, escaping root paths, and duplicate normalized paths. Allow additional fields. Drop flagged files before selection.
- `scan(root: string, options: Options, runner: ProcessRunner): Promise<FileMetric[]>`; root is validated absolute directory from composition root. Produces source-selected metrics or throws an actionable error.

- [ ] **RED:** Add stubs and a recording fake runner (queued results/errors). Use fixed scc-shaped JSON to assert Lines is used rather than Code, language and relative path retained, zero accepted, and extra fields ignored. Assert empty array returns empty, but truncated JSON, missing Files, negative/fractional/nonfinite/nonsafe metrics, wrong field types, duplicate paths and `../outside.ts` throw. Include absolute in-root paths and non-ASCII/spaced paths.
- [ ] **RED:** Assert scan request argv starts `['scc','--no-config','--by-file','--format','json','--no-min-gen']`, passes the excluded directories explicitly, ends with `.`, and uses root as cwd. Assert a directory containing shell metacharacters never appears in shell source. Assert nonzero exit and rejected spawn produce errors; stderr controls are escaped and diagnostics capped at 4096 characters. Assert generated/minified/binary records are omitted and custom exclusion still wins.
- [ ] Run `bun test tests/grain-scanner.test.ts`; confirm failures for missing behavior.
- [ ] **GREEN:** Implement decoder and scan against the injected runner, without creating real subprocesses. Always apply source policy after normalization. Retain cause context in errors without showing raw terminal controls.
- [ ] Run `bun test tests/grain-*.test.ts` and `git diff --check`; require all pass.
- [ ] Commit both tracks: `feat(grain): adapt scc output through a testable process boundary`.

### Task 3: OpenTUI dashboard, launcher and chezmoi deployment

**Interfaces:**
- Consumes model/scanner exports from Tasks 1–2.
- `mountDashboard(renderer: CliRenderer, files: readonly FileMetric[], quit: () => void): () => void` in ui.ts; returns idempotent cleanup.
- main.ts constructs the concrete ProcessRunner with Bun.spawn and argument arrays, drains stdout/stderr concurrently, parses options, validates directory/TTY, scans once, constructs renderer, wires cleanup, and exits nonzero on failures. No dependency construction in model/scanner.

Pin TypeScript and Bun type development dependencies to concrete compatible versions resolved at implementation time; record the lockfile. Do not alter Todoist dependencies. Add grain node_modules ignore rules before installing locally.
- [ ] Implement composition root and renderer lifecycle. Handle help before prerequisite/TTY checks; diagnostics go to stderr. Use both stdin/stdout TTY checks.
