# Temporary worktrees implementation plan

> **For agentic workers:** Use executing-plans to implement these steps inline.

**Goal:** Provide `wt new`, `wt merge`, and `wt remove` through chezmoi.

**Architecture:** One Python standard-library executable. A Worktrees service owns lifecycle policy; an injected repository adapter owns Git, filesystem, and temporary directory effects. Store each sandbox's base branch and absolute checkout path in one local Git config value under its branch.

**Tech Stack:** Python 3, argparse, subprocess, Git worktrees, unittest.

**Spec:** User-approved conversation: branch from current local branch (or explicit `--base`), merge with a merge commit into recorded base then clean up, refuse unmerged or dirty removal unless `--force`. No main/master special cases. Only remove managed linked worktrees. Commit and push in chezmoi, then apply.

## Files

- `dot_local/bin/executable_wt`: CLI, lifecycle service, production adapter.
- `tests/wt.test.py`: deterministic unit tests with in-memory repository fake.
- `docs/qa/wt.py`: discretionary real-Git QA, never an automated unit suite.
- `docs/wt.md`: usage, recovery, safety limits.

## Review focus

- Detached HEAD requires an explicit local base branch.
- Conflicts must retain both branches and the sandbox for recovery.
- Dirty/untracked work, locked worktrees, and unmanaged paths must not be silently deleted.
- Slash-containing branch names and paths with spaces must work without shell interpolation.
- Removing a branch used as another sandbox's base must be refused even with force.

  flagged as QA-policy mismatches. New real-Git tests live only under `docs/qa/`.

Implementation choices: ignored files follow Git's disposable-build-output
semantics; cleanup never recursively deletes unexpected container contents.
Concurrent lifecycle operations and manual branch/worktree renames are not
supported. These limits are explicit in `docs/wt.md`.
